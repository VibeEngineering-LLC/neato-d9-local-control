Метод — сниффер (nrf-ble-sniffer) + разведка.

## В сети

Робот виден в локальной сети по WiFi как «Neato-Robot». OUI его MAC — `08:3A:88` = Neato Robotics.
(Конкретные адреса/топология сети в публичной версии опущены.)

## BLE (по снифферу)

- Базовый захват эфира 25 с (`ble_20260915_180032_neato_baseline.pcap`) — Neato по BLE НЕ рекламировался
  (в простое на базе молчит). Нужен режим сопряжения / пробуждение.

## Результат разведки 2026-09-15 (подтверждено источниками)

**WiFi — доказанный тупик:**
1. Облако Neato/Vorwerk отключено **30.11.2025** (офиц. объявление 06.10.2025). MyNeato, pybotvac,
   HA-интеграция мертвы — авторизация идёт через выключенные серверы.
2. Локального WiFi-API у D9 НЕТ. Только исходящее TLS в `orbital.neatocloud.com:3443` с cert pinning.
   Fake-cloud через DNS-спуфинг сообщество провалило (02.2026, робот рвёт TLS на unknown CA).
3. Аппаратные проекты **OpenNeato / fang** D8/D9/D10 НЕ поддерживают — прочитано лично в README
   (raw.githubusercontent, github заблокирован встроенным браузером): дословно
   «D8/D9/D10 are NOT supported (different board, password-locked serial port)». Управление там — UART
   debug-порт (вскрытие + ESP32), у D9 порт под паролем; BLE в проекте не участвует.

**BLE — единственный неисследованный вектор:**
4. BLE у D-серии документирован ТОЛЬКО для онбординга (передача WiFi-кредов). RE протокола команд
   публично не найден. Даже успешный онбординг бесполезен для управления (облако мертво, локального
   API нет) — смысл есть, только если в GATT найдутся характеристики команд уборки. Проверяется снятием
   GATT-карты `Neato Robot Services` (`08:3a:88:XX:XX:XX`).

## Скрипты

- `_spec_gatt_scan.md` + `neato_gatt_scan.py` — GATT-разведка через bleak (только read, без write).
