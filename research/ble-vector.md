# BLE-вектор Neato D9 — единственный неисследованный программный путь

## Что известно

- BLE у Neato D-серии документирован ТОЛЬКО для первичной настройки (онбординг): телефон по BLE
  подключается к роботу и передаёт WiFi-креды. Управление уборкой по BLE публично НЕ описано, RE
  GATT-протокола команд не найден (research 2026-09-15).
- Источник онбординга: https://support.neatorobotics.com/support/solutions/articles/204000039614

## Что нашли сниффером (2026-09-15)

Захваты (на C:, приватность — см. `../captures/README.md`):
- `ble_20260915_180032_neato_baseline.pcap` — пылесос на базе спит, по BLE НЕ рекламируется.
- `ble_20260915_180710_neato_awake.pcap` — пылесос разбужен: **появился** `08:3a:88:XX:XX:XX`,
  имя **`Neato Robot Services`**, RSSI −46, PDU `0x00/0x03/0x04` (connectable), 158 пакетов/35 с.

BLE-MAC = WiFi-MAC + 1 (`...81:dc` → `...81:dd`).

## Ключевой момент (честная оценка)

Даже если BLE поддастся — если там ТОЛЬКО онбординг, это переподключит робота к WiFi, которым всё равно
нечем управлять (облако мертво, локального API нет — см. `wifi-cloud-deadend.md`). Смысл BLE-пути есть,
ТОЛЬКО если в GATT-таблице найдутся характеристики команд (start/clean/dock/status), а не одна настройка.
Это и проверяет снятие GATT-карты.

## Вывод (окончательный, снят с устройства)

**BLE у D9 — ЧИСТО онбординг: настроить WiFi (сканер сетей + запись SSID/пароля, зашифрованных
Robot_Public_RSA_Key) и привязать робота к облаку (Linking). Ни одной характеристики команд уборки
(clean/dock/pause/state/battery) НЕТ.** Управление уборкой у D9 идёт только через облако по WiFi.

Значит по BLE управлять уборкой нельзя — вектор закрыт. НО характеристика **Linking** потенциально важна
для соседнего вектора: если найдётся живое облако, принимающее D9 (см. `kobold-vr7.md`), BLE-Linking —
штатный механизм привязки робота к нему.

## Что дальше (не тупик целиком)

- Прямого BLE-управления нет — доказано.
- Живой Kobold/Vorwerk API v2 (`kobold-vr7.md`) + BLE-Linking — единственная связка, ведущая к рабочему
  облаку. Проверять там.

## Безопасность

- Только READ на этапе разведки. WRITE в неизвестное устройство — опасно (можно нарушить работу),
  только после понимания протокола и с явного согласия оператора.
- Устройство принадлежит оператору, разрешение на изучение есть. Чужие BLE-устройства из захвата
  (соседи) — не трогать, не публиковать их адреса.
